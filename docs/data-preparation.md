# Prepare the test and figure data

Install the [core environment](environment.md#core-environment), then run from the repository root:

```bash
python scripts/prepare_data.py --profile all --output runs/data-preparation.json
python scripts/verify_release.py --tables
```

The distribution prepares only the test evaluation and paper-figure inputs described here. It does not recreate the omitted training sequences, supplementary benchmark, full experimental sequence or image-processing weights.

## What is calculated

The 3D test preparation starts from the published shortlist of 566,261 candidates and the complete smoothed test trajectories. Candidate geometry and its 24 candidate-generation features are retained. The original routines calculate 53 further trajectory features, yielding the 77-feature table. The prepared output preserves the original row order and feature definitions.

Tiny floating-point and serialization differences are recorded separately as integer bitwise differences. Applying them after calculation recovers the original file exactly, including missing values and metadata. They do not replace the trajectory calculation. The full table, not just a sample, is checked against its original SHA-256. Subsequent scoring and image-enriched tables are assembled from this table, stored score fields and supplied image measurements.

The test particle-state table is generated by the original 6,000-frame simulator, using seed 260745, its fixed parameters, code and empirical sampling distributions. Its original SHA-256 is checked too. [Simulation contract](simulation.md).

The comparison methods' final input features, fixed candidate geometry for coverage evaluation, reference predictions, and measured figure inputs are supplied. Preparing these inputs does not rerun their image detector or tracking pipeline.

## Select a workflow

| Profile | Prepared inputs | Additional completed files |
| --- | --- | ---: |
| `all` or `paper` | All supported workflows | 1.30 GB |
| `evaluation` | Three pretrained models and Tables 3–4, including the 3D trajectory-feature calculation | 1.11 GB |
| `figures` | All nine figures; regenerates test particle truth and prepares reference event predictions and numerical figure measurements | 0.20 GB |

```bash
python scripts/prepare_data.py --profile evaluation --output runs/evaluation-inputs.json
python scripts/prepare_data.py --profile evaluation --verify-only
```

Use `--list` to list the profile's outputs. Dependencies are prepared automatically. Profiles can be combined by running them successively. `verify_release.py --tables` requires the complete `all` profile; use `--verify-only` with the chosen profile for partial preparation.

The sizes above exclude temporary files and software environments. Allow 6 GB of additional disk space for full preparation, excluding software environments. On the verification host, full preparation took 14.4 minutes. The feature calculation and particle simulation account for most of that time; runtime depends on hardware.

## Resume and verify

Each completed file must match its recorded size and SHA-256 checksum, a fingerprint of its complete contents, before installation. Approximate matches are rejected. Repeating a command reuses completed files with matching checksums. If an existing file differs, preparation identifies it and stops without overwriting it. Move that file aside before retrying.

The report records completed paths, environment versions and checksums. `data_sources/recipes.json` identifies each output and dependency; `reference/expected_outputs.json` records the selected table schemas. `manifest.json` lists files actually distributed. Prepared tables are ignored by Git.

## Recalculate a small feature sample

After full preparation, the following command independently repeats the 3D trajectory calculation for 500 fixed candidates and compares all 77 features with the reference:

```bash
python scripts/recompute_static_features.py --max-candidates 500 --output runs/feature-sample
```

The 24 candidate-generation features remain fixed. Use `--max-candidates 0` for the full shortlist. This sample check reports the unadjusted numerical differences; data preparation additionally applies the recorded bitwise differences and checks complete-file identity.
