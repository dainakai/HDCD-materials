# 102.3 mm・位相回復3回版の全量評価

2026-11-01に開始し、11月2日に完了した、旧画像や旧特徴量を流用しない数値ホログラム評価です。`amt_preflight_20261030`の固定入力比較とは別の実験です。[結果manifest](results/manifest.json)から数値とFig.7–9を参照できます。中間生成物と詳細な実行記録は、リポジトリの隣にある`audit/revision-full-20261101/`に保存しています。

全3手法で公開版よりAP・最大F1・FP80・FP90が改善しましたが、複数の条件と生成正解が変わるため、総差を位相回復3回だけの効果とは解釈しません。Oursでは画像特徴を加えた段階のFP80が177→183件となり、すべての指標が段階ごとに改善したわけではありません。

同じモデルと候補によるR4の対照では、OursとDepth-freeは抑制前、MinIP-based 2Dは抑制後のAPが高い結果でした。主評価は事前に固定した抑制前のままです。新テストで再選択していません。

最終のFig.9描画だけが依存ライブラリの読み込み順で失敗しました。`figure9.py`で共通の環境初期化を先に行うよう修正し、`finish_campaign.py`で図と成果物整理を再開しました。修正前後のモデル・性能評価ファイルのハッシュ一致を保存しています。画像と学習をやり直す修正ではありません。

## 固定した条件

- 生成体積Zは0–102300 µm。連続的な粒子運動を維持し、再構成面は100 µm間隔の1024面。
- 主カメラから74,900–177,200 µm、カメラ間隔21,450 µm。全ての位相回復を3回。
- 生成・計測・MinIPのpadding1536、衝突画像特徴のpadding2048。既存条件を保持。
- MinIPは元の200 µmずつの伝搬計算を維持し、0,2,…,1022面の後に1023面を追加。最初の512面が従来計算とbit単位で一致することを検証。
- R4は全3手法で座標抑制前の順位を保持。新しいモデルで抑制後順位も推論し、候補・座標が同一であることを確認して差を報告する。新テストの結果で採用規則を選び直さない。
- R5はt−1の親2粒子とt+1の娘粒子の観測IDを優先し、補間しない。fallback、neutral、イベント重み、クラス重みを統一。attentionは保持されたtop20で再ラベル化。
- Oursの教師対応にはZ±15,000 µm。比較2手法では深度を使わない。テストの対応は全手法共通で±5 frames、XY350 µm、Zなし、最大一対一対応。
- APはprecision envelopeの積分。非補間のrecall加重precisionも別値として保存する。
- 学習seed260740–260744、評価260745。旧生成でこのテストseedを感度分析に使った履歴は開示する。

## 入力と隔離

新しい正解は`audit/revision-preflight-20261030/generation/seed*/labels/`にある生成済み6系列を使います。CSVとParquet、画像と正解、モデルと評価入力はハッシュで対応付けます。旧モデル、旧画像特徴、旧静的特徴、旧候補集合は本評価の入力にしません。

計測のソースと4個のモデルは、元のproduction環境から219 MBの独立snapshotへ複製しました。`production-source.json`で内容を固定し、`initialize.py`で照合します。外部のモデルや元研究データを書き換えません。CUDA Pythonは既存GPU環境を利用し、キャッシュは本作業ディレクトリに保存します。

`frozen_engine/`は本評価用の衝突検出・linker・smootherコードです。`bootstrap.py`が`engine-manifest.json`と実行用コピーを照合します。物理Z原点、全手法の順位規則、MinIP読込み精度もここで固定しています。Depth-freeのMinIPは公開版同様float32、MinIP-based 2Dはfloat64です。10月29日の実験との比較では、この精度条件の復帰も区別してください。

## 実行

このホストの既定パスは`bootstrap.py`と`common.py`にあります。GPU0を使用し、他の処理が使うGPU1は変更しません。

```bash
.venv/bin/python experiments/amt_full_20261101/pipeline.py
```

流れは、各系列のホログラム生成→MinIP→粒子計測→3D/2D追跡、全系列の候補生成→上流学習と選別→特徴抽出→3手法の再学習→共通評価→Fig.7–9です。CPUの追跡は次系列のGPU処理と並行します。

実行中の二重起動はlockで拒否します。検証済みの生成チャンクとMinIP画像はハッシュ確認後に再利用します。未確認の画像や不一致を黙って上書きしません。失敗した段階は`campaign-state.json`と`logs/`に記録されます。計測などで不完全な出力が残った場合は、その段階のログと既存ファイルを確認してから再開します。

`finish_when_ready.py`は本体成功後に一度だけ`finalize.py`を実行します。最終モデル3個の配布用archive、表3・4のTeX、数値転記表、旧本文の主張を維持できるかの判定、実験レビュー用のモデル固定記録を作ります。既存原稿や既存レビューラベルは更新しません。

## 完了確認と成果物

- `campaign-state.json`：本体の完了または失敗。
- `finalized.json`：入力・モデル・評価の照合、成果物整理の完了。
- `results/{ours,depth_free,minip2d}/`：PR、AP、FP80/90、最大F1、候補recall、独立なSciPy対応照合。
- `results/*/rank_sensitivity.json`：同じモデル・同じ生存候補の順位固定順の比較。
- `results/table4/`：共通後処理を明示した段階比較。全重複抑制を外した比較は別保存。
- `results/figure07/`：新しい低confidence検出、同じ衝突テスト軌跡による粒子計測誤差と分布。旧PRは流用しない。
- `manuscript/claim-checks.json`：Oursが両比較法より良いか、段階追加で単調に良くなるかを実測で確認。
- `artifacts/hdcd-amt-102p3mm-phase3-models.tar.gz`：モデル3個と対応する実行コード。

`manuscript-changes.json`に、数値以外の修正案を用意しています。順位の定義、教師のZゲート、AP定義、Table4の共通後処理、テスト利用履歴は、図表と数値だけでは解消しません。

実験再処理は今回のモデルが固定された後に行います。14系列の準備資料と旧レビュー1,120件は保存済みです。元の実験画像ドライブが見えていないため、完全な実験再処理はまだ実施していません。合成に使った旧実験分布は固定し、新しい実験統計で遡及的に置き換えません。

## 検証

18件の関連単体検証と、128フレーム・26,289点・551軌跡・8,747候補の接続確認が通過しました。接続確認は学習や最終性能表に混ぜません。3手法の特徴抽出は32候補のサンプルで接続を確認し、科学的な最終値は全量処理から得ます。

スマホ用HTMLの更新には`publish_progress.py --watch`を使います。公開先は既存のQuick Tunnelです。集計JSONと完成した図だけを報告書allowlistに追加し、生の研究データやリポジトリは配信しません。
